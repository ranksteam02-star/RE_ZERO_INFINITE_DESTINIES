# เป้าหมายเกมระยะยาว — เล่น 7–8 เดือน

## ความต้องการที่ Owner ยืนยัน

เล่นเฉลี่ย **2–3 ชั่วโมงต่อวัน** ต่อเนื่องประมาณ **7–8 เดือน**. ใช้สมมติฐาน 30 วันต่อเดือน เท่ากับช่วงเป้าหมายประมาณ **420–720 ชั่วโมง**. เป็นเป้าหมายออกแบบระยะยาว ไม่ใช่เวลาเล่นที่รุ่น 0.4 มีแล้ว และไม่ใช่กำหนดระยะเวลาพัฒนา

## สถานะจริงของรุ่น 0.4

- มีบทนำ 6 ตอน, 152 dialogue nodes, 12 decision points และ 4 endings
- หนึ่งรอบอ่าน 104 dialogue pages; ยังไม่ได้จับเวลาจากผู้เล่นจริงเพื่อระบุจำนวนชั่วโมง
- มีลานเมืองขนาดเล็กหนึ่งฉากให้เดินและเริ่มบทสนทนา
- ยังไม่มี battle, quests, inventory, timeline reset หรือแผนที่หลายพื้นที่
- 4,096 ชุดตัวเลือกใน automated test ไม่เท่ากับ 4,096 เรื่องที่มีเนื้อหาไม่ซ้ำ

## โครงสร้างเกมที่ต้องรองรับ

1. **เนื้อเรื่องหลักหลาย Arc:** แต่ละ Arc มีเป้าหมายเฉพาะ ความขัดแย้ง ตัวละคร ผลจากตัวเลือกเดิม และจุดพักที่บันทึก/กลับมาเล่นต่อได้
2. **เส้นทางตัวละคร:** Trust/Affection/Suspicion/Fear/Resentment เปิดเหตุการณ์และมุมมองต่างกัน; ไม่ให้ค่าเดียวตัดสินทุกความสัมพันธ์
3. **เควสต์และการสำรวจ:** quest journal, เงื่อนไขเริ่ม/สำเร็จ/ล้มเหลว, NPC schedules, พื้นที่เชื่อมกัน, ของรางวัลและผลต่อโลก
4. **Turn-based combat:** ระบบเทิร์น สกิล resource management ศัตรูที่มีกลยุทธ์ และการปรับทีม/อุปกรณ์
5. **Timeline และความทรงจำ:** checkpoint snapshot, กฎ resettable/persistent, knowledge unlocks, ผลของความรู้จากรอบก่อนต่อทางเลือกใหม่
6. **Replay ที่มีผลลัพธ์ต่าง:** บทสนทนา เหตุการณ์ พันธมิตร และฉากจบที่ต่างจริง พร้อมระบบข้ามข้อความที่เคยอ่าน
7. **รองรับการกลับมาเล่น:** หลายช่อง Save, autosave ที่แยกจาก manual save, backlog, journal สรุปเรื่อง, migration และ content versioning

## หลักวางปริมาณเนื้อหา

ยังไม่ล็อกตัวเลขชั่วโมงรายระบบก่อนมี vertical slice ที่จับเวลาได้. ให้ใช้การเล่นจริงกำหนดระยะเวลาต่อบท/เควสต์/encounter แล้วจึงคำนวณจำนวนเนื้อหาที่ต้องผลิต

แยกชัดระหว่าง:

- เวลารอบแรกจนจบเนื้อเรื่องหลัก
- เวลาเนื้อหารองที่ยังไม่เคยเห็น
- เวลาสำรวจ/ต่อสู้ที่มีเป้าหมาย
- เวลาเล่นใหม่เพื่อเส้นทางอื่น

ช่วง 420–720 ชั่วโมงอาจนับเวลารวมหลายเส้นทาง แต่ไม่ควรเรียกทั้งหมดว่าเนื้อเรื่องใหม่ของรอบแรก. ต้องระบุบนหน้าเกมว่าจำนวนชั่วโมงหมายถึงประเภทใดและวัดจากอะไร

## Milestones ตามลำดับ

### M1 — Vertical slice ของ RPG (งานชุดถัดไป)

วงจร: สำรวจลานเมือง → รับเควสต์ → คุย/เลือกทาง → ต่อสู้หนึ่ง encounter → ได้ผลลัพธ์ → ส่งเควสต์ → บันทึก/โหลด

งานจำเป็น: QuestManager แบบ data-driven, journal, BattleManager พื้นฐาน, battle result → story/quest effects, state schema และ migration fixtures. สร้างแค่เควสต์หนึ่งเรื่องและศัตรูชุดเล็กก่อน เพื่อพิสูจน์การเชื่อมระบบ

Quality gate: เล่นครบด้วยเมาส์/คีย์บอร์ด, ไม่รับรางวัลซ้ำ, โหลดกลางขั้นตอนได้, victory/defeat มีปลายทางชัดเจน, ไม่มีข้อมูลหาย

### M2 — เครื่องมือสำหรับเรื่องยาว

หลาย Save slots, autosave, backlog, read-text skip, quest summary, chapter packs, content validator ที่หา unreachable nodes และ missing localization. Save v1 ต้องมี migration แบบทดสอบซ้ำได้ก่อนเปลี่ยนรูปแบบ

### M3 — Timeline slice

กำหนดกฎ persistence ร่วมกับ Owner, ทำ checkpoint เดียว, death-return flow หนึ่งแบบ และเหตุการณ์ที่ knowledge จากรอบก่อนเปิดทางใหม่. ห้ามใช้ New Game reset แทน timeline restoration

### M4 — Arc เต็มหนึ่งชุดและ playtest

เพิ่มพื้นที่/เควสต์ที่ใช้ระบบผ่าน M1–M3 แล้ว. เก็บเวลาต่อกิจกรรมจากการเล่นทดสอบและตรวจความต่อเนื่องของเรื่อง. ใช้ผลนี้ตัดสินจำนวน Arc และปริมาณเนื้อหาที่ผลิตไหวสำหรับ solo development

### M5 — ขยาย content packs

เพิ่ม Arc/แผนที่/ศัตรู/เส้นทางเป็นชุดที่เล่นจบได้. แต่ละชุดมี save compatibility tests, regression routes, balance checks และ release notes. ประเมินชั่วโมงเนื้อหาใหม่ที่เพิ่มขึ้นจากผลทดสอบ ไม่ใช่จากจำนวน node อย่างเดียว

## สิ่งที่ยังต้องตัดสินใจเมื่อถึงระบบนั้น

- จำนวนตัวละครที่ควบคุมได้และขนาด party
- รูปแบบ skill/resource progression
- เงื่อนไข death-return และ checkpoint ที่ Owner อนุมัติ
- สัดส่วนเนื้อเรื่องหลัก/เนื้อหารอง/การเล่นซ้ำ
- แหล่งและขั้นตอนผลิต art/audio เพิ่มเติม

เป้าหมายระยะยาวนี้ไม่เปลี่ยนข้อกำหนด Godot 4, GDScript, Windows PC, ภาษาไทย และสถาปัตยกรรม 2.5D. การวางแผนไม่ถูกนับเป็นฟีเจอร์ที่ส่งมอบแล้ว
